## 한 줄 요약

- 공개키 암호화는 암호화에 쓰는 공개키는 배포하고, 복호화에 쓰는 비밀키는 소유자가 안전하게 관리하는 비대칭키 방식이다.

## 한눈에 보는 구조

```mermaid
flowchart LR
    A["송신자"] --> B["수신자의 공개키로 암호화"]
    B --> C["암호문"]
    C --> D["수신자의 비밀키로 복호화"]
    D --> E["평문"]
```

## PDF 기준 핵심

- 데이터를 암호화할 때 사용하는 공개키(Public Key)는 데이터베이스 사용자에게 공개한다.
- 복호화할 때의 비밀키(Secret Key)는 관리자가 비밀리에 관리한다.
- 암호화 대상이 n개일 때 사용되는 키의 개수는 2n이다.
- 대표적으로 RSA(Rivest Shamir Adleman)가 있다.

## 개념 설명

- 공개키 암호화는 공개키와 비밀키가 수학적으로 연결된 한 쌍의 키를 사용한다.
- 누구나 공개키로 암호화할 수 있지만, 해당 비밀키를 가진 사람만 복호화할 수 있다.
- 디지털 서명에서는 반대로 비밀키로 서명하고 공개키로 검증하는 방식도 사용된다.
- NIST 키 관리 지침은 대칭키와 비대칭키의 키 관리 특성을 구분해 설명한다.

## 시험 포인트

- `공개키는 공개, 비밀키는 관리자가 비밀 관리`가 PDF 핵심이다.
- 키 개수는 `2n`으로 출제될 수 있다.
- RSA는 공개키 암호화 대표 알고리즘이다.
- 개인키 암호화는 동일 키 사용, 공개키 암호화는 키 쌍 사용이다.

## 헷갈리는 비교

| 구분 | 개인키 암호화 | 공개키 암호화 |
|---|---|---|
| 키 구조 | 하나의 공유 키 | 공개키/비밀키 쌍 |
| 키 개수 | n(n-1)/2로 비교 출제 가능 | 2n |
| 속도 | 빠름 | 상대적으로 느림 |
| 대표 | AES, DES | RSA |

## 예시 또는 암기 포인트

- 사용자가 서버의 공개키로 메시지를 암호화하면, 서버는 자신의 비밀키로만 복호화할 수 있다.
- 암기식: `공개키는 열쇠 구멍, 비밀키는 여는 열쇠`.

## 상세 보강

```mermaid
flowchart LR
    A["송신자"] --> B["수신자의 공개키로 암호화"]
    B --> C["암호문"]
    C --> D["수신자의 개인키로 복호화"]
    D --> E["평문"]
```

- 공개키 암호화는 공개키와 개인키 한 쌍을 사용하는 비대칭키 암호 방식이다.
- 공개키는 배포해도 되지만 개인키는 소유자가 비밀로 보관해야 한다.
- 기밀 통신에서는 수신자의 공개키로 암호화하고 수신자의 개인키로 복호화한다.
- 전자서명에서는 개인키로 서명하고 공개키로 검증하는 흐름을 사용한다.
- PDF의 `암호화 대상이 n개일 때 키 개수 2n`은 사용자마다 공개키·개인키 2개가 필요하다는 의미로 기억한다.

| 구분 | 공개키 암호화 | 개인키 암호화 |
|---|---|---|
| 키 구성 | 공개키 + 개인키 | 동일한 비밀키 |
| 속도 | 느림 | 빠름 |
| 키 분배 | 상대적으로 쉬움 | 안전한 공유 필요 |
| 대표 | RSA | AES, DES |
