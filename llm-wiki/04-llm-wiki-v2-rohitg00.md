## 1. 프로젝트 개요

Karpathy의 LLM Wiki 원본에 **agentmemory**(프로덕션급 AI 에이전트 메모리 시스템) 구축 경험을 반영한 확장 프레임워크. 원본이 "아이디어 파일"이었다면, v2는 "프로덕션에서 부딪히는 문제들의 해법"을 추가한 것이다.

**핵심 컨셉**: "위키는 살아있는 유기체다. 지식은 태어나고, 성장하고, 때로는 죽어야 한다."

## 3. 메모리 수명 관리 (Memory Lifecycle)

원본에서 가장 크게 보완한 영역. "모든 지식은 동등하지 않다"는 전제에서 출발.

### 3-1. 신뢰도 점수 (Confidence Scoring)

모든 팩트에 메타데이터 부여:

```yaml
fact: "React 19는 Server Components를 기본 지원한다"
confidence: 0.92
sources: 3              # 이 주장을 지지하는 소스 수
last_reinforced: 2026-04-08
contradictions: 0       # 반박하는 소스 수
```

- 소스가 많을수록 → 신뢰도 상승
- 모순이 발견되면 → 신뢰도 하락 + 플래그
- 오래되면 → 시간 기반 감쇠

### 3-2. 대체 (Supersession)

새 정보가 기존 주장을 업데이트할 때:

```
[기존] React 18은 Concurrent Mode를 실험적으로 지원
    ↓ superseded by
[신규] React 19는 Concurrent Features를 정식 지원 (2025-01)
```

- 기존 주장은 **삭제되지 않고 "대체됨" 표시**
- 타임스탬프와 링크로 이력 보존
- 언제, 무엇에 의해 대체되었는지 추적 가능

### 3-3. 망각 (Forgetting) — Ebbinghaus 곡선

```
보존율
  │
  │ ████
  │   ████
  │      ████                    ← 강화(reinforcement)마다
  │         ████                    곡선 리셋
  │            ████
  │               ████████████████████
  │
  └──────────────────────────────── 시간
```

**핵심 원리**: "보존은 시간에 따라 지수적으로 감쇠하지만, 강화할 때마다 곡선이 리셋된다."

| 지식 유형 | 감쇠 속도 | 예시 |
|-----------|----------|------|
| 아키텍처 결정 | 느림 | "마이크로서비스 채택 이유" |
| API 스펙 | 보통 | "엔드포인트 URL 형식" |
| 일시적 버그 | 빠름 | "npm 캐시 클리어로 해결" |

→ 자주 참조되는 지식은 살아남고, 안 쓰이는 지식은 자연스럽게 비중이 줄어듦

## 4. 지식 계층 (Consolidation Tiers)

인지 과학의 기억 모델을 차용:

```
┌──────────────────────────────────────┐
│        Procedural Memory             │  가장 압축, 가장 오래 지속
│    (워크플로우, 패턴, 습관)            │  "어떻게 하는지"
├──────────────────────────────────────┤
│        Semantic Memory               │  크로스 세션 팩트
│    (일반화된 지식, 개념)              │  "무엇인지"
├──────────────────────────────────────┤
│        Episodic Memory               │  세션 요약
│    (특정 경험, 사건)                  │  "무엇이 일어났는지"
├──────────────────────────────────────┤
│        Working Memory                │  가장 상세, 가장 짧게 지속
│    (최근 관찰, 현재 작업)             │  "지금 무엇을 하는지"
└──────────────────────────────────────┘
```

**승격 메커니즘**: 증거가 축적되면 하위 → 상위 계층으로 자동 승격

```
Working → "이 빌드가 실패했다" (일회성 관찰)
    ↓ 3번 반복
Episodic → "이번 주에 같은 빌드 실패 3회 발생"
    ↓ 패턴 확인
Semantic → "CI에서 메모리 제한으로 인한 빌드 실패가 빈번함"
    ↓ 해결법 정립
Procedural → "빌드 전 항상 캐시 클리어 + 메모리 제한 확인"
```

## 5. 구조화된 지식 그래프

플랫 마크다운 페이지를 넘어, 타입된 엔티티와 관계를 명시적으로 표현:

### 엔티티 추출

```yaml
entities:
  - name: "React"
    type: library
    attributes:
      version: "19.1"
      maintainer: "Meta"
  
  - name: "Server Components"
    type: concept
    attributes:
      introduced_in: "React 18"
      status: "stable"
```

### 타입된 관계

```
React ──uses──▶ Server Components
React ──depends_on──▶ Node.js
Server Components ──contradicts──▶ Client-only Rendering
React 19 ──caused──▶ RSC 마이그레이션 트렌드
```

관계에 의미(semantic weight)가 있으므로:
- **키워드 검색**이 놓치는 연결을 **그래프 순회**로 발견 가능
- "React와 관련된 모든 모순을 보여줘" 같은 구조적 질의 가능

## 6. 확장 검색 (Search at Scale)

위키가 ~100 페이지를 넘으면 index.md만으로는 부족:

```
┌─────────┐   ┌──────────────┐   ┌────────────────┐
│  BM25   │ + │ Vector Search │ + │ Graph Traversal │
│(키워드) │   │  (시맨틱)     │   │   (관계 기반)    │
└────┬────┘   └──────┬───────┘   └───────┬────────┘
     │               │                    │
     └───────────────┼────────────────────┘
                     ▼
          Reciprocal Rank Fusion
          (결과 통합 랭킹)
```

- **BM25**: 정확한 키워드 매칭 (stemming 포함)
- **Vector Search**: 의미적으로 유사한 콘텐츠 발견
- **Graph Traversal**: 관계를 따라가는 구조적 탐색
- **Reciprocal Rank Fusion**: 세 검색의 결과를 통합 랭킹

## 7. 이벤트 드리븐 자동화

수동 트리거를 제거하고, 이벤트 기반으로 자동 실행:

| 이벤트 | 자동 액션 |
|--------|----------|
| 새 소스 추가 | Auto-ingest (읽기 → 요약 → 위키 업데이트) |
| 세션 시작 | Context injection (L1 로드 + 최근 활동 요약) |
| 세션 종료 | Session compression (대화 → 핵심 요약으로 압축) |
| 메모리 쓰기 | Contradiction detection (기존 주장과 모순 검사) |
| 주기적 (cron) | Lint + Consolidation (정리 + 승격) |
| 망각 임계값 도달 | Decay processing (비중 축소 또는 아카이브) |

## 8. 품질 관리 + 자가 치유

### 품질 점수
모든 LLM 생성 콘텐츠에 자체 평가 또는 2차 프롬프트로 품질 점수 부여

### 자가 치유 (Self-healing)
| 문제 | 자동 대응 |
|------|----------|
| 고아 페이지 (인바운드 링크 없음) | 관련 페이지에 링크 추가 또는 아카이브 제안 |
| 오래된 주장 | 최신 소스와 대조 후 업데이트 제안 |
| 깨진 참조 | 자동 수정 또는 삭제 |
| 모순 | 소스 권위도 + 최신성 기반으로 교정안 제시 |

## 9. 멀티 에이전트 협업

### 메시 동기화
여러 에이전트가 병렬로 작업한 관찰을 공유 위키에 병합

### 스코프 관리
```
Agent A의 관찰 (private) ──┐
                           ├──▶ 공유 팩트로 롤업
Agent B의 관찰 (private) ──┘
```

### 경량 조정
에이전트 간 중복 작업 방지 (누가 무엇을 처리 중인지 추적)

## 10. 프라이버시 & 거버넌스

- **Ingest 필터링**: API 키, 크레덴셜, PII 자동 제거
- **감사 로그**: 모든 오퍼레이션에 타임스탬프 + 근거 기록
- **가역적 벌크 연산**: 삭제, 내보내기, 병합을 되돌릴 수 있음

## 11. 결정화 (Crystallization)

완료된 탐구 체인을 구조화된 다이제스트로 증류:

```
탐구 질문 → 발견 사항 → 관련 엔티티 → 교훈
```

→ 탐구 결과 자체를 소스로 취급하여 다시 ingest

## 12. 핵심 인사이트

> "스키마 문서가 가장 중요한 파일이다."

스키마가 인코딩하는 것:
- 엔티티 타입 정의
- Ingest 규칙
- 품질 기준
- 모순 해결 정책
- 통합 스케줄
- 도메인별 특화 규칙

→ 제네릭 LLM을 **훈련된 지식 관리자**로 변환하는 핵심 설정

## 13. 점진적 도입 경로 (Implementation Spectrum)

한 번에 다 구현할 필요 없이, 필요에 따라 점진적으로 추가:

```
Level 1: 기본        Sources + Pages + Schema (Karpathy 원본 수준)
Level 2: 수명 관리    + Confidence scoring + Supersession + Decay
Level 3: 구조화      + Entity extraction + Typed relationships
Level 4: 자동화      + Event-driven hooks + Auto-ingest
Level 5: 확장        + Hybrid search + Graph traversal
Level 6: 협업        + Multi-agent sync + Governance
```

## 14. 관련 개념

- **Ebbinghaus 망각 곡선 (1885)**: 학습한 정보의 보존율이 시간에 따라 지수적으로 감소한다는 심리학 이론. 반복 학습(spaced repetition)으로 감쇠를 늦출 수 있음
- **인지 과학의 기억 분류**: Working memory (작업 기억), Episodic (일화 기억), Semantic (의미 기억), Procedural (절차 기억)의 4단계 분류 체계
- **Knowledge Graph**: 엔티티와 관계를 노드-엣지 구조로 표현하는 방식. Google Knowledge Graph, Wikidata가 대표적
- **Reciprocal Rank Fusion (RRF)**: 여러 검색 시스템의 결과를 하나의 랭킹으로 통합하는 기법
- **Event-driven Architecture**: 이벤트 발생 시 자동으로 핸들러가 실행되는 아키텍처 패턴
- **Supersession**: 새 버전이 이전 버전을 대체하되 이력을 보존하는 패턴. 법률/규정 체계에서 차용한 개념

## 15. 이용 페르소나

### 페르소나 A: 장기 리서치 프로젝트 연구자
- **프로필**: 수개월~수년에 걸쳐 한 주제를 깊게 파는 연구자/박사과정
- **고민**: 초기 논문의 주장이 이후 논문에서 반박되었는데, 위키에는 둘 다 남아있음
- **사용 흐름**: Supersession으로 대체 관계 명시 → 신뢰도 점수로 현재 유효한 주장 파악 → 망각 곡선으로 오래된 정보 자동 감쇠
- **가치**: 지식의 진화를 추적할 수 있는 살아있는 위키

### 페르소나 B: AI 에이전트 운영자
- **프로필**: 여러 AI 에이전트를 운영하며 공유 지식을 관리해야 하는 MLOps 엔지니어
- **고민**: 에이전트 A가 발견한 사실을 에이전트 B가 모름. 중복 작업 발생
- **사용 흐름**: 메시 동기화로 에이전트 간 관찰 공유 → 스코프 관리로 private/shared 분리
- **가치**: 멀티 에이전트 환경에서의 지식 일관성

### 페르소나 C: 기업 지식 관리 책임자
- **프로필**: 사내 위키/문서가 방대하지만 관리가 안 되는 조직의 CTO/VP of Engineering
- **고민**: 2년 전 문서가 여전히 검색되고, 현재와 모순되는 정보가 혼재
- **사용 흐름**: 점진적 도입 (Level 1 → 6) → 자동 lint + self-healing → 거버넌스 + 감사 로그
- **가치**: 자가 유지되는 기업 지식 시스템

## 16. 장단점

### 장점
- 가장 이론적으로 완성도 높은 프레임워크
- 인지 과학, 정보 검색, 분산 시스템의 개념을 종합적으로 적용
- 점진적 도입 가능 (Level 1부터 시작)
- 멀티 에이전트, 거버넌스 등 기업 수준 요구사항 고려

### 단점
- 아이디어 문서 (gist)이지, 실행 가능한 코드가 아님
- 완전 구현 시 복잡도가 매우 높음
- Ebbinghaus 곡선의 파라미터 튜닝이 도메인마다 필요
- 실제 프로덕션 검증 사례가 부족
