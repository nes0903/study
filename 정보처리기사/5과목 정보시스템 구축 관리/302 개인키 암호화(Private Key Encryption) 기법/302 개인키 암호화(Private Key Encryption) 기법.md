## 한 줄 요약

- 개인키 암호화는 암호화와 복호화에 동일한 키를 사용하는 방식으로, 알고리즘이 단순해 처리 속도가 빠르다.

## 한눈에 보는 구조

```mermaid
flowchart LR
    A["평문"] --> B["동일한 비밀키로 암호화"]
    B --> C["암호문"]
    C --> D["동일한 비밀키로 복호화"]
    D --> E["평문 복원"]
```

## PDF 기준 핵심

- 동일한 키로 데이터를 암호화하고 복호화한다.
- 알고리즘이 단순하므로 암호화/복호화 속도가 빠르다.
- 시험 표현의 개인키 암호화는 대칭키 암호화와 같은 의미로 이해한다.

## 개념 설명

- 대칭키 암호화는 송신자와 수신자가 같은 비밀키를 공유한다.
- 키가 노출되면 암호화와 복호화가 모두 가능하므로 키 배포와 보관이 중요하다.
- AES, DES, SEED, ARIA 같은 블록 암호가 대표 예로 출제된다.
- 공개키 암호화보다 일반적으로 빠르므로 대량 데이터 암호화에 적합하다.

## 시험 포인트

- `동일한 키`가 핵심이다.
- 속도가 빠르다는 PDF 문구를 기억한다.
- 공개키 암호화는 공개키와 비밀키 한 쌍을 사용한다.
- 키 개수 문제에서는 n명이 서로 안전하게 통신하려면 대칭키는 보통 `n(n-1)/2`개가 필요하다고 비교될 수 있다.

## 헷갈리는 비교

| 구분 | 개인키/대칭키 | 공개키/비대칭키 |
|---|---|---|
| 키 | 동일한 키 하나 | 공개키와 비밀키 |
| 속도 | 빠름 | 느림 |
| 키 관리 | 공유 키 보관이 중요 | 공개키 배포 가능 |
| 대표 | AES, DES | RSA |

## 예시 또는 암기 포인트

- 같은 비밀번호로 파일을 암호화하고 다시 그 비밀번호로 여는 방식은 대칭키 암호화에 가깝다.
- 암기식: `개인키는 같은 키로 잠그고 푼다`.

## 빠른 복습

- 개인키 암호화의 키 사용 방식은? 동일한 키로 암호화와 복호화.
- 속도 특징은? 빠르다.
- 대표 알고리즘은? DES, AES, SEED, ARIA 등.

## 상세 보강

```mermaid
flowchart LR
    A["평문"] --> B["동일한 비밀키로 암호화"]
    B --> C["암호문"]
    C --> D["동일한 비밀키로 복호화"]
    D --> E["평문"]
```

- 개인키 암호화는 암호화와 복호화에 같은 키를 사용하는 대칭키 암호 방식이다.
- 알고리즘이 비교적 단순하고 빠르므로 대량 데이터 암호화에 적합하다.
- 단점은 송신자와 수신자가 같은 비밀키를 안전하게 공유해야 한다는 점이다.
- 키가 유출되면 암호화와 복호화가 모두 가능하므로 키 관리가 매우 중요하다.
- 시험에서는 `동일한 키`, `속도가 빠름`, `대칭키`, `비밀키 공유 문제`를 함께 기억한다.

| 구분 | 개인키/대칭키 | 공개키/비대칭키 |
|---|---|---|
| 키 | 같은 키 | 공개키와 개인키 쌍 |
| 속도 | 빠름 | 느림 |
| 용도 | 대용량 데이터 암호화 | 키 교환, 전자서명 |
| 키 관리 | 공유 비밀키 보호 필요 | 개인키 보호 필요 |
